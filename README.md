# PlugManReloaded

[![Build & Test](https://github.com/MilkyWayTop16/PlugManReloaded/actions/workflows/build.yml/badge.svg)](https://github.com/MilkyWayTop16/PlugManReloaded/actions/workflows/build.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)
[![Java: 16+](https://img.shields.io/badge/Java-16%2B-orange.svg)](https://www.oracle.com/java/)
[![Platform: Paper | Purpur | Folia](https://img.shields.io/badge/Platform-Paper%20%7C%20Purpur%20%7C%20Folia-brightgreen.svg)](https://papermc.io)

Менеджер плагинов для серверов Minecraft на базе **Paper 1.16.5+**, **Purpur** и **Folia**. Позволяет управлять плагинами во время работы сервера: загружать, выгружать, перезагружать, искать новые версии и устанавливать обновления без рестарта. Включает динамический анализ графа зависимостей (DAG), многоуровневую очистку памяти (Metaspace) и защиту сетевого стека Netty.

Команды: `/plugmanreloaded`, `/plugman`, `/plm`.

> [!NOTE]
> **Преемственность:** PlugManReloaded продолжает развитие идей оригинальных проектов PlugMan (RyanTheAllmighty, drtshock) и PlugManX (Test-Account666), адаптируя их к современному API Paper и многопоточному ядру Folia. Проект независимый: по всем вопросам и баг-репортам используйте [Issues](https://github.com/MilkyWayTop16/PlugManReloaded/issues), не обращаясь к авторам оригиналов.

> [!WARNING]
> Ядра Spigot и CraftBukkit не поддерживаются: плагин намеренно блокирует запуск на них при старте, чтобы не нарушать целостность данных сервера.

## Совместимость: честно о границах возможного

Выгрузка плагинов на лету не была задумана архитекторами Bukkit и Paper как штатная процедура. Платформа сервера умеет корректно снимать только то, что зарегистрировано через её официальный API: слушателей событий, задачи планировщика, сервисы, команды и каналы сообщений. Всё, что плагин создал в обход API — статические ссылки, нативные библиотеки JNI, кэши сторонних библиотек — сервер отследить и вернуть не может.

Это фундаментальное свойство архитектуры загрузчиков классов Java (`ClassLoader`). С ним сталкиваются любые менеджеры плагинов, включая оригинальный PlugMan. У Paper есть открытая проблема [PaperMC/Paper#786](https://github.com/PaperMC/Paper/issues/786) с утечками Metaspace при повторной регистрации слушателей, а автор ProtocolLib прямо предупреждает, что горячая перезагрузка его плагина не поддерживается.

PlugManReloaded не скрывает эти ограничения. Вместо пустых обещаний он предупреждает о рисках и предотвращает повреждение сервера.

### Что не меняет состояние плагинов

Команды `/plm list` и `/plm info` только читают данные и полностью безопасны в любой момент.

### Что работает с большинством плагинов

Команды `/plm load`, `/plm enable`, `/plm disable`, `/plm unload`, `/plm reload` и `/plm restart` стабильно работают с подавляющим большинством плагинов: экономикой, мини-играми, командными утилитами и механизмами. На современном Paper отключение плагина может закрывать его загрузчик классов, поэтому повторное включение автоматически поднимает свежий экземпляр из файла JAR. При полной выгрузке PlugManReloaded снимает официальные регистрации сервера и проводит глубокую очистку оставшихся ссылок (подробнее в разделе [Очистка памяти](#как-устроена-очистка-памяти)).

### Что не будет работать на лету — и почему

Некоторые плагины физически нельзя безопасно выгрузить без полного перезапуска сервера:

| Категория | Примеры | Причина |
|---|---|---|
| Плагины сетевого стека (Netty) | ProtocolLib, ViaVersion, ViaBackwards, ViaRewind, ProtocolSupport | Модифицируют Netty-пайплайн сервера при старте. При выгрузке пакетные слушатели теряют регистрацию, а висящие обработчики приводят к сбоям сетевого потока. |
| Прокси-мосты | Geyser-Spigot, Floodgate | Инжектируются в сетевую обработку пакетов глубже стандартного API плагинов. |
| Нативные библиотеки (JNI) | Плагины с `.so` / `.dll` / `.dylib` | Повторный вызов `System.loadLibrary()` в той же виртуальной машине завершается фатальным `UnsatisfiedLinkError`: JVM запрещает повторную загрузку одной и той же библиотеки. |
| Защита от перезапуска в JVM | SkinsRestorer | Содержит внутренний предохранитель от повторного запуска в одной JVM (`SkinsRestorer was already loaded in this JVM`). |
| Трансформация байткода | WorldEdit, FastAsyncWorldEdit | Используют глубокую модификацию классов и тяжелые маппинги. Повторная инициализация замораживает главный поток сервера и вызывает аварийную остановку по Watchdog. |
| Paper-плагины с Bootstrapper | Плагины с `PluginBootstrap` / `PluginLoader` | Архитектура Paper не предоставляет API для runtime-выгрузки таких плагинов. |

Для таких плагинов PlugManReloaded по умолчанию **отказывается выполнять выгрузку без прямого подтверждения**. Список задаётся в `config.yml` в параметре `settings.unsafe-to-unload`:

```yaml
settings:
  unsafe-to-unload:
    - "LuckPerms"
    - "Vault"
    - "PlaceholderAPI"
    - "SkinsRestorer"
    - "FastAsyncWorldEdit"
    - "WorldEdit"
    - "WorldGuard"
    - "Essentials"
    - "MoneyFromMobs"
    - "ProtocolLib"
    - "ViaVersion"
    - "ViaBackwards"
    - "ViaRewind"
    - "ProtocolSupport"
    - "Geyser-Spigot"
    - "floodgate"
    - "packetevents"
```

Список можно свободно дополнять или сокращать. Дополнительно плагин сканирует классы загрузчика цели: если внутри обнаруживаются маркеры Netty или JNI, защита сработает даже для неизвестного форка или переименованного файла.

### Плагины-провайдеры API

Vault, LuckPerms, PlaceholderAPI и WorldEdit сами по себе выгружаются без сбоев. Проблема в другом: на них завязаны десятки зависимых плагинов через `ServicesManager` или прямой импорт классов. Если выгрузить провайдер API при работающих зависимых, они начнут выбрасывать `IllegalPluginAccessException` и `NoClassDefFoundError`.

PlugManReloaded отслеживает связи через граф зависимостей (`depend`/`softdepend`) и сервисы Bukkit. Для таких случаев предназначена каскадная перезагрузка (`-c`), которая перезапускает провайдер вместе со всеми зависимыми в правильном топологическом порядке.

### Безопасный режим (`safe-mode`)

Включён по умолчанию. При попытке выгрузить опасный плагин команда приостанавливается и запрашивает подтверждение кнопкой в чате или флагом `-y`:

```text
/plm unload ProtocolLib
> ⚠ Плагин ProtocolLib встраивается в сетевой стек сервера при запуске
> и корректно выгрузиться не может. Нужен перезапуск сервера!
> [Выгрузить всё равно]   [Отменить]
```

Для пропуска подтверждения в скриптах используйте флаг `-y`: `/plm unload <плагин> -y`.

### Поддерживаемые платформы

| Компонент | Поддерживаемая версия |
|---|---|
| Платформы | Paper, Purpur, Folia |
| Версии Minecraft | 1.16.5 и новее (`api-version: 1.16`) |
| Версия Java | Java 16 и новее |
| Не поддерживаются | Spigot, CraftBukkit (запуск отклоняется) |

На Folia при отключении плагина отменяются его глобальные, асинхронные и сущностные задачи. На современном Paper (1.19.3+) используется нативный `PaperPluginManagerImpl`.

## Как устроена очистка памяти

При выполнении операций `unload`, `restart` и каскадных перезагрузках PlugManReloaded проводит санитарию ресурсов:

1. Снимает регистрации сервисов, слушателей событий, задач планировщика и каналов сообщений через Bukkit API.
2. Отключает хуки PlaceholderAPI, ProtocolLib и PacketEvents, если они присутствуют.
3. Сканирует Netty-пайплайны подключённых игроков и удаляет обработчики выгружаемого плагина.
4. Закрывает открытые кастомные инвентари у игроков и очищает временные права (`PermissionAttachment`).
5. Прерывает фоновые потоки, привязанные к `ClassLoader` плагина, с обнулением контекстного загрузчика.
6. Разрегистрирует JDBC-драйверы, открытые плагином.
7. Очищает кэши `Introspector` и внутренние связи загрузчиков Paper.
8. Закрывает `URLClassLoader` плагина.

Эти меры сводят риск утечки памяти к минимуму, доступному без вмешательства в исходный код ядра сервера.

### Разрешения (Permissions)

По умолчанию все права выдаются операторам сервера (`op`).

| Право | Назначение |
|---|---|
| `plugmanreloaded.admin` | Полный доступ ко всем командам и функциям менеджера |
| `plugmanreloaded.notify` | Получение уведомлений о выходе обновлений при входе на сервер |
| `plugmanreloaded.update.source` | Разрешение привязывать проект к источнику обновлений через чат |

## Обновление плагинов

Команда `/plm update` проверяет и обновляет установленные плагины:

```text
/plm update                    Проверить все плагины (только диагностика, ничего не качает)
/plm update <плагин>           Проверить один плагин и показать кнопку установки в чате
/plm update <плагин> -y        Установить обновление сразу
/plm update all -y             Обновить все плагины с подтверждёнными источниками
```

### Распознавание проектов

1. Сначала плагин вычисляет контрольную сумму SHA-1 установленного JAR-файла и сверяет её с базой Modrinth. При точном совпадении проект и версия определяются гарантированно без догадок по названию.
2. Если файл модифицирован или отсутствует в базе, используется каталог известных плагинов и поиск по главному классу дескриптора. Такие совпадения требуют ручного подтверждения кнопкой перед установкой.

### Поддерживаемые площадки

| Площадка | Проверка версии | Каналы (alpha/beta) | Автоматическая установка |
|---|:---:|:---:|:---:|
| Modrinth | Точно по версии MC | Поддерживаются | Да |
| Hangar | Точно по версии MC | Поддерживаются | Да |
| GitHub Releases | По тегам и веткам | Пометка pre-release | По кнопке с подтверждением |
| SpigotMC | Без метаданных ядра | Нет | Уведомление со ссылкой |
| RuSpigot | Через поле исходного кода | Нет | С подтверждением (при наличии GitHub) |
| Jenkins CI | Сборочные билды | Сборки как alpha | По кнопке с подтверждением |

Платные плагины со SpigotMC и RuSpigot защищены: плагин выводит уведомление о выходе новой версии и прямую ссылку на покупку. Бесплатные аналоги вместо купленного плагина не подставляются.

### Пользовательские источники (`sources-custom.yml`)

Если редкий плагин отсутствует на крупных площадках, привяжите его вручную в файле `plugins/PlugManReloaded/sources-custom.yml`:

```yaml
plugins:
  CustomPlugin:
    sources:
      - id: github
        ref: "AuthorName/CustomPlugin"
```

Источники также можно привязывать прямо из игры: если источник не найден, нажмите кнопку **[Указать источник]** в чате и отправьте ссылку на страницу проекта.

### Безопасность при установке обновлений

- Скачивание происходит в изолированную временную папку.
- Контрольная сумма и внутренний дескриптор `plugin.yml` сверяются до замены файла.
- Предыдущая версия автоматически сохраняется в `plugins/.plugmanreloaded-backups/`.
- При неудачном запуске новой версии плагин выполняет автоматический откат к рабочей резервной копии.
- Плагины сетевого стека (`ProtocolLib`, `ViaVersion`) не выгружаются на лету: файл помещается в папку отложенных обновлений сервера и применится при плановом перезапуске.

## Скачивание новых плагинов

Команда `/plm download` находит и устанавливает новые плагины с Modrinth, Hangar, SpigotMC и GitHub:

```text
/plm download <URL>                  Скачать плагин по ссылке на проект
/plm download <название>             Поиск плагина с показом интерактивных карточек
/plm download <название> -y          Скачать с автоматическим подтверждением зависимостей
/plm download <название> -s modrinth Искать только на конкретной площадке
/plm download <название> -w          Скачивать также мягкие зависимости (--with-soft-deps)
```

1. **Скоринг результатов:** система ранжирует проекты по совпадению имени, платформе сервера и популярности, отсекая устаревшие форки.
2. **Разрешение зависимостей (DAG):** плагин анализирует обязательные (`depend`) и опциональные (`softdepend`) связи, сопоставляет их с установленными плагинами и предлагает докачать недостающие компоненты в один клик.
3. **Двухфазная транзакция (2PC):** файлы проверяются на сигнатуры архивов, допустимую версию Java-байткода и корректность манифеста. Если на этапе запуска одного из модулей возникает ошибка, транзакция полностью откатывается.

## Локализация и конфигурация

Плагин полностью поддерживает два языка: русский и английский. Язык задаётся параметром в `config.yml`:

```yaml
settings:
  language: ru   # ru или en
```

После редактирования примените изменения командой `/plm config reload`. Перезапуск сервера не требуется.

Переключение языка затрагивает три слоя:
- Сообщения в чате и кликабельные кнопки (`messages/ru-messages.yml`, `messages/en-messages.yml`).
- Консольные логи и служебные сообщения (`messages/logs/ru-logs.yml`, `messages/logs/en-logs.yml`).
- Комментарии внутри `config.yml` (плагин переписывает подсказки на выбранный язык, аккуратно сохраняя все ваши значения параметров).

## Developer API

PlugManReloaded предоставляет программный API для плагинов, систем автотестов и панелей управления.

Для обращения к API укажите зависимость в `plugin.yml`:
```yaml
softdepend: [PlugManReloaded]
```

### Подключение через Maven

```xml
<dependency>
    <groupId>ru.milkyway</groupId>
    <artifactId>PlugManReloaded</artifactId>
    <version>1.0</version>
    <scope>provided</scope>
</dependency>
```

### Использование API

Все методы API потокобезопасны. Вызовы из асинхронных потоков автоматически синхронизируются с главным потоком сервера.

```java
import ru.milkyway.plugmanreloaded.api.PlugManAPI;
import ru.milkyway.plugmanreloaded.api.PluginResult;
import ru.milkyway.plugmanreloaded.api.PluginInfo;

// Быстрая перезагрузка плагина
PluginResult result = PlugManAPI.reload("DecentHolograms");
if (result.isSuccess()) {
    long elapsed = result.getElapsedMs();
}

// Загрузка, выгрузка и переключение состояний
PlugManAPI.load("MyPlugin.jar");
PlugManAPI.unload("MyPlugin");
PlugManAPI.enable("MyPlugin");
PlugManAPI.disable("MyPlugin");

// Получение метаданных
Optional<PluginInfo> info = PlugManAPI.getInfo("LuckPerms");
info.ifPresent(p -> {
    String version = p.version();
    long size = p.fileSizeBytes();
});
```

### События жизненного цикла (Bukkit Events)

Вы можете перехватывать и отменять операции через стандартную систему событий:

| Событие | Cancellable | Когда срабатывает |
|---|:---:|---|
| `PluginPreLoadEvent` | Да | Перед загрузкой JAR-файла (после проверки сигнатур и версии Java) |
| `PluginLoadedEvent` | Нет | После успешной загрузки и инициализации плагина |
| `PluginPreUnloadEvent` | Да | Перед началом выгрузки плагина из памяти |
| `PluginUnloadedEvent` | Нет | После завершения выгрузки (содержит имя плагина строкой) |
| `PluginPreReloadEvent` | Да | Перед началом перезагрузки плагина |
| `PluginReloadedEvent` | Нет | После успешного завершения перезагрузки с временем выполнения |
| `PluginUpdateFoundEvent` | Нет | При обнаружении новой версии установленного плагина |

Пример слушателя:

```java
@EventHandler
public void onPreUnload(PluginPreUnloadEvent event) {
    if (event.getPluginName().equalsIgnoreCase("CriticalSecurityPlugin")) {
        event.setCancelled(true);
    }
}
```
